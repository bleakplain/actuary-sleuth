# QA 综合回答质量与延迟优化调研

调研日期：2026-10-16（Asia/Shanghai）。范围：保险产品法规问答，不覆盖公司经营、销售管理等无关场景。本轮仅调研与制定方案，未运行新模型、改运行代码或切换生产配置。

## 1. 结论

推荐 **结构完整的证据召回 + 一次高质量生成 + 按风险、按失败类型执行有限修复**，而不是继续叠加通用校验，也不是关闭全部校验。投入顺序是：定位真实失败与耗时 → 改善证据覆盖及表格语义 → 评估单次生成能力 → 精简校验/修复路径 → 小规模补充共用概念层。

行业资料支持“先轻后重、证据不足才补检索”，但不证明任一框架或模型能令本项目达到 95% 准确率。最新版 Azure 官方实现也区分轻量检索和按需深入检索，并限制补检索次数；相关能力仍有 preview 条件，不是要求本项目迁移 Azure。[Azure 检索推理强度](https://learn.microsoft.com/en-us/azure/search/agentic-retrieval-how-to-set-retrieval-reasoning-effort)

## 3. 一手来源逐项核查

### S1：上下文增强检索，不是无限扩充 prompt

- 来源：[Anthropic — Introducing Contextual Retrieval](https://www.anthropic.com/engineering/contextual-retrieval)，2024-09-19。
- 结论：为块添加其在原文中的简短上下文，同时用于向量和 BM25 索引，再融合、重排。其 top-20 检索失败率从 5.7% 降到 1.9%，**这是特定实验检索指标，不是回答准确率**。
- 应用：索引文本带法规标题、章条路径、适用对象、表格名称；引用仍指向未改写原文。优先确定性元数据，缺上下文的块再自动补摘要。
- 限制：不照搬 top-150/top-20 或外推中文保险法规收益。生成的上下文是检索辅助，不是法条证据。

### S2：结构化分块与父子关联是可参考的工程模式

- 来源：[Microsoft — 按文档布局分块](https://learn.microsoft.com/en-us/azure/search/search-how-to-semantic-chunking)，页面更新 2026-06-08。
- 结论：按标题、段落等布局分块，保留父文档 ID 和标题层次；官方示例使用健康计划文档。
- 应用：小块用于命中，父级条款包用于生成；按同文档、同版本、同条款/同表展开，而不是简单追加左右若干块。保留正文、例外、表头、脚注的关联。
- 限制：借鉴数据模型，不必采用云服务；自动结构识别仍需样本检验，解析成功不等于内容完整。

### S3：表格不应只剩 Markdown 行

- 来源：[Docling — Chunking](https://docling-project.github.io/docling/concepts/chunking/)、[Serialization](https://docling-project.github.io/docling/concepts/serialization/)，动态官方文档，访问 2026-10-16，不据此推断发布日期。
- 结论：HybridChunker 在层次分块后按 token 调整，支持跨块重复表头；Markdown 不保留合并单元格结构，JSON/HTML 能保留相关结构。
- 应用：保留行列、合并表头、单位、比例基数、边界词、适用段落；检索用文本投影，校验和展示回到结构数据/原文。
- 限制：先抽查高频数值表格，再决定复用现有解析器还是局部接入；不因工具存在就全量重解析 Word，也不假设具体文件已识别正确。

### S4：2026 年官方产品仍是按需升级，不是每问多轮 agent

- 来源：[Azure — Retrieval reasoning effort](https://learn.microsoft.com/en-us/azure/search/agentic-retrieval-how-to-set-retrieval-reasoning-effort)，访问 2026-10-16，明确涉及 2026-08-01-preview API。
- 结论：minimal 不调用 LLM 规划；low 单次规划；medium 在结果不足时最多补检索一次；auto 先轻量、必要时升级。额外推理增加延迟和费用；preview 不受生产 SLA 保障。
- 应用：按复杂度与证据缺口路由，设置请求预算，最多一次针对性修复；简单问答不强制经过 LLM 解释、全文评审和全文重写。
- 限制：借鉴控制策略，不照搬 API，不把预览产品当作成熟合规方案。

### S5：Adaptive-RAG 的支持点是动态分配计算

- 来源：[Adaptive-RAG，NAACL 2024](https://aclanthology.org/2024.naacl-long.389/)，2024-06；[作者代码](https://github.com/starsuzi/Adaptive-RAG)。
- 结论：按复杂度选择不同强度路径，避免简单问题无谓迭代、复杂问题只检索一次。
- 应用：先用可解释条件和离线评估做路由，不立即训练分类器。法规事实即使走快路径也保留检索，不套用论文的无检索分支。
- 限制：开放域实验不能推导中文法规质量；多跳、跨版本、错误前提需独立测试。

### S6：修复证据缺口，不是同一模型反复“再想想”

- 来源：[Corrective RAG](https://arxiv.org/abs/2401.15884)，首次提交 2024-01-29；[LLMs Cannot Self-Correct Reasoning Yet](https://arxiv.org/abs/2310.01798)，首次提交 2023-10-03。
- 结论：CRAG 根据检索质量选择动作；后一研究针对缺乏外部反馈的内生纠错，发现其不稳定，不意味着有证据反馈的纠错都无效。
- 应用：分别处理不足、矛盾、引用映射错误、服务超时。只有缺证据才补检索；矛盾带原文和冲突字段改写；格式本地修正；超时不视为事实错误。
- 限制：CRAG 的开放网页补检索不直接适用于法规权威性要求。联网核验须限定官方来源、记录日期版本，并遵守外部数据权限。

### S7：Self-RAG 不是多加一次普通提示词校验

- 来源：[Self-RAG，ICLR 2024](https://arxiv.org/abs/2310.11511)，首次提交 2023-10-17。
- 结论：通过训练引入反思 token，按需检索并判断相关性和支持度；不是给任意模型加“请检查”即可复制。
- 决策：借鉴按需与细粒度支持，暂不做反思 token 训练、自建专用验证模型或多轮全文反思。
- 限制：需要训练及评测数据，不能把论文能力直接赋给当前免费模型。

### S8：引用存在、引用支持、回答正确是不同维度

- 来源：[ALCE，EMNLP 2023](https://aclanthology.org/2023.emnlp-main.398/)，2023-12；[RAGTruth，ACL 2024](https://aclanthology.org/2024.acl-long.585/)，2024-08。
- 结论：ALCE 分开衡量流畅度、正确性和引用质量；RAGTruth 用人工标注分析 RAG 中的无依据或矛盾陈述。
- 应用：确定性检查管 ID/版本、数字、单位、上下限、日期；概率判断处理语义疑点。离线分别统计引用支持精度、关键主张覆盖、完整度和误拒率。
- 限制：NLI/LLM judge 可出错，不是法律真值；每句话有引用不等于准确或合规。

### S9：2026 年法律 RAG 研究仍发现错误前提难题

- 来源：[How Much Do Legal RAG Systems Still Hallucinate?](https://arxiv.org/abs/2608.14210)，2026-08-14；[全文](https://arxiv.org/html/2608.14210v1)。
- 结论：比较 8 个配置、英文 GDPR 与法文民法，另有 142 个专家问题；强调按主张、答案、严重性和问题类型分析，错误前提问题较难。
- 应用：保留“所有产品死亡保额都固定为某比例吗”等反例；既不能顺着前提误答，也不应拒绝本可纠正的误解。
- 限制：预印本，法域、语种、问题、模型不同；不把其幻觉率当本项目或 ima 的测量。

### S10：最新法律引用检测也可能误放行“合理但无支持”的内容

- 来源：[When Citations Mislead? / PARCEL](https://arxiv.org/abs/2610.10971)，2026-10-07；[全文](https://arxiv.org/html/2610.10971v1)。页面声明 ICAIL 2026，本文不独立背书其出版状态。
- 结论：纽约州判决的 3,396 个主张分为 supported/refuted/not found；缺失支持比直接矛盾更难检测，提供全文也仍有误放行。
- 应用：保留 supported/contradicted/insufficient，timeout/error 另列；重点测无依据主张被误判正确，而非只测总判别准确率。
- 限制：非常新的单法域研究；最佳分类准确率不是端到端问答准确率，也不构成本项目 95% 保证。

### S11：GraphRAG 有问题类型边界

- 来源：[Microsoft GraphRAG — Query Engine](https://microsoft.github.io/graphrag/query/overview/)，动态官方文档，访问 2026-10-16。
- 结论：local 结合实体图与原文；global 对社区报告做 map-reduce，官方说明其资源消耗大；同时保留 basic search。
- 决策：当前是条款、数值、适用范围，暂不做全库图谱、社区摘要或全局 map-reduce。只有跨法规关系问题经对照实验受益才局部引入。
- 限制：自动关系/摘要不天然可靠，仍须原文、时效和版本，不能替代法规治理。

### S12：轻量概念层可复用标准，不等于一键获得中国保险规则

- 来源：[W3C SKOS Primer](https://www.w3.org/TR/skos-primer/)，2009-08-18；[EDM Council FIBO](https://edmcouncil.org/frameworks/industry-models/fibo/)，动态页面，访问 2026-10-16。
- 结论：SKOS 支持标签、别名、广狭义和相关关系；broader 本身不声明传递性。FIBO 是可复用的开放金融概念本体。
- 应用：复用已有共享概念注册表，增加高频分类、别名和带来源的关系；JSON/关系表即可。把本地分类层级与 SKOS 词表关系区分。
- 限制：词义相近不等于法律等同，上下位关系不意味着规则无条件继承；通用 FIBO 不能自动补齐中国保险产品范围、例外与生效时间。

### S13：降低人工成本，不等于取消人工校准

- 来源：[ARES，NAACL 2024](https://arxiv.org/abs/2311.09476)，首次提交 2023-11-16，2024-03-31 修订。
- 结论：用合成数据训练评估器，以少量人工标注校准预测；报告效果依赖其具体方法与数据。
- 应用：从失败日志和原文生成候选问题、要点和错误变体；人审关键边界、分歧、高风险缺口，不逐条写答案。
- 限制：同一模型出题、回答、打分可能共同犯错；合成集不是独立金标，仍需冻结真实问法的人工小样本。论文的人工数量不是本项目质量保证。

### S14：ima 是体验对标，不是已知架构或 95% 的证据

- 来源：[腾讯 ima 官方产品页](https://ima.tencent.com/download)，访问 2026-10-16。
- 官方能力：多格式知识导入、知识库信源召回、结合模型回答、原文溯源。
- 边界：本次查看的官方页没有给出可比较的中国保险法规准确率或完整私有检索/校验/本体架构。不能宣称 ima 不校验、用了 GraphRAG 或天然达到 95%。
- 对标：获授权使用同一文档，同语料、问题、知识边界盲评；区分联网补充与知识库回答；测可用性、关键错误、引用和时延，不凭主观相似度。

### S15：相关证据不等于足够回答的证据

- 来源：[Google Research — Sufficient Context](https://research.google/blog/deeper-insights-into-retrieval-augmented-generation-the-role-of-sufficient-context/)，2025-05-14；[ICLR 2025 论文入口](https://research.google/pubs/sufficient-context-a-new-lens-on-retrieval-augmented-generation-systems/)。
- 结论：区分上下文是否足够回答，可把检索不足与模型未利用充分证据的失败拆开；相关性分数不能替代充分性。
- 应用：离线对比“当前上下文”与“人工/结构化补全证据包”，再比较同一模型输出，决定先改召回还是生成。在线先用方面覆盖、表格依赖和已有生成结构暴露缺口，不默认每问新增独立充分性模型调用。
- 限制：特定模型/数据集结果不是本项目模型能力上限；上下文足够也不保证模型答对。

### S16：2026 Google Agentic RAG 的关键是明确缺什么再补什么

- 来源：[Google Research — Agentic RAG](https://research.google/blog/unlocking-dependable-responses-with-gemini-enterprise-agent-platforms-agentic-rag/)，2026-06-05。
- 结论：对复杂跨源请求拆分查询；检视片段和草稿，生成具体缺口反馈，引导补检索后综合，而非仅输出 insufficient。
- 应用：概述问答漏了某类适用情形，应生成“缺少哪一方面及为何需要”的有界反馈，再做一次针对性召回。与当前盲目全文重写区别很大。
- 限制：厂商多 agent 工作流及其“up to”收益不能直接外推本地中文保险法规；本项目不复制全部 agent，更不让每问走该重路径。只在离线实验发现收益后启用复杂问题支路。

## 4. 推荐架构：少做重复工作，把证据准备充分

下列为本项目工程建议，不是已被外部资料验证的性能承诺。

1. **统一问题对象。** 保留原始问法；只有依赖前文的追问才用会话上下文。别名/概念扩展只用于检索，不改用户意图；独立问题不带旧产品限制。
2. **证据先完整再生成。** 继续 hybrid/rerank，最后组包增加条款去重、方面覆盖、结构依赖。概述不能被同一司法解释的相似块挤满。
3. **召回与回答单元分开。** 小块命中，生成用含适用段、表头、数据行、单位、脚注、例外的条款包；只沿同版本依赖展开并控制 token。
4. **先做单次生成对照。** 固定优质证据包，比较当前模型与获授权候选模型的初稿可交付率、严重错误、费用、时延，不默认校验器能弥补模型全部弱项。
5. **按风险检查。** 所有答案快速查来源/版本/结构；数字、上下限、法定期限、适用判断、跨版本结论必须检查。普通术语解释经引用与范围检查后可不调用全文 LLM judge。不能用流式输出掩盖高风险核对未完成。
6. **一次针对性补救。** 格式本地修正，缺口补检索，矛盾仅修订受影响主张。预算不足返回已支持部分与具体缺口，不强制全文重写。
7. **交付状态诚实。** 完整、部分支持、原文参考、需澄清、服务失败分别统计。原文参考不算综合问答成功；进度事件与真实正文分别测时。

| 失败类型 | 首选动作 | 不应混淆 |
| --- | --- | --- |
| 词面不同、证据充分 | 针对争议主张做语义判断 | 不自动视为无依据 |
| 缺关键方面或例外 | 针对缺口补召回一次 | 不是同一 prompt 重发 |
| 数字、单位、上下限、范围矛盾 | 局部重写并复验 | 不能为降低拒答而放行 |
| 引用编号/格式错误 | 可确定时规范化，否则重新定位 | 不能编造来源 |
| 服务超时/解析失败 | 独立错误状态，预算内恢复或已支持内容降级 | 不等于无资料或已核验 |
| 来源/生效日/修订关系缺失 | 标记效力待核验，另列元数据工作 | 不能靠模型猜成现行有效 |
| 用户前提错误 | 有据纠正前提并解释适用范围 | 不顺从误答，不必全拒绝 |

## 5. 共用本体的最小边界

- **共用：** 概念 ID、别名、产品分类、责任类型、同义/上下位/相关关系及证据、确认状态。
- **各自保留：** QA 更大的法规范围、证据和发布清单；合规审核自己的规则触发、条件、门槛和版本。
- **不自动继承：** “重疾属于疾病保险”帮助找到上位条款，但仍需检查当前产品、合同、责任、生效时间，不能直接生成合规结论。
- **低成本：** 从已有关系和失败样本自动提议边，人只确认影响检索/适用的核心关系。不手工做全库三元组，不编写海量口语表达。
- **有边界发布：** 区分机器提议与确认关系；未确认关系可作检索线索，不作硬性合规推导。

概念层缓解术语分类问题，不能解决表格丢失、生成漏条件或法规效力未知，不是本轮改进的前置大工程。

## 6. 小人工评估方案

以下是起步估算，不是已完成测量或最终质量承诺。
本节给出研究阶段选项；实际首轮范围、分工和人工预算以同目录 [优化计划](plan.md) 第 6 节为准，不能把两份文档的不同估算相加或视为报价。

- 冻结 30–40 个真实代表问题，覆盖概述、数值、口语、跨法规、追问、话题切换、错误前提及时间/地区/产品限定；另自动生成约 80–120 个同义/反事实变体作开发集，两者分开计数。
- 人工只标适用范围、必答事实、原文位置、不可错约束、是否需澄清，不写完整范文。
- 专家先核 10–15 个高风险问题和核心关系，其余工具预标、分歧抽检。若原文和标签已准备，初轮可按 **3–6 小时** 排期；法规效力逐份核验另列成本。
- 每轮自动回放；每周集中审高风险/高频新增失败，可先预算 30–60 分钟，按实测异常量调整。
- 同模型生成和评分不算独立真值。小样本用于找回归和比较方案，不足以声称 95% 准确；对外可靠性声明要独立分层测试、样本量和置信区间。

| 环节 | 分别观测 | 原因 |
| --- | --- | --- |
| 检索 | 必需证据 Recall@k、最终方面覆盖、同条款冗余 | 候选命中不代表生成拿到完整证据 |
| 生成 | 初次可交付率、关键事实正确率、范围完整度 | 不让重写/兜底掩盖初稿不足 |
| 引用 | 存在率、支持精度、关键主张覆盖 | 有链接不等于支撑结论 |
| 校验 | 错误放行、正确误拦、服务失败 | 降拒答可能增加误答 |
| 体验 | 真正文首段、总时延 p50/p95、完整率、原文兜底率 | 进度动画和原文堆叠不等于专业回答 |
| 治理 | 官方来源/生效日/修订关系覆盖、未知效力占比 | 忠实原文不等于法律现行适用 |

## 7. 优先与暂缓

**优先：** 固定基线与消融；最终证据去重覆盖；表格/适用段完整；单次生成能力对照；局部修复；高风险校验；渐进补来源/效力元数据。

**暂缓：** 全库 GraphRAG、大规模人工规则化、本体大工程、多轮全文反思、微调、自建 judge、数据库迁移、口语硬编码、盲目扩大 top-k、全部关校验。

**另行授权事项：** 付费模型预算、向新外部服务发送法规、自动联网入库、大范围重建索引。调研本身不授权这些实施动作。

## 8. 未决项

1. 当前模型在固定优质证据包上的能力上限，需正式对照确认。
2. 漏项源自重排、去重、截断还是块元数据，需 trace/代码消融定位。
3. 53 份法规效力缺失须单独治理，手册标题含 2026 不证明每份现行。
4. 原文兜底应独立计量，避免只改变拒答文案而未提升综合问答。
5. ima 私有架构、可比较准确率与本项目最终上限均未知；只能用同条件测试证明改进。
