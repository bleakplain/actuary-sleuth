# Feature Specification: Compliance Tag Taxonomy

**Feature Branch**: `035-compliance-tag-taxonomy`
**Created**: 2026-07-21
**Status**: Approved
**Input**: 建立连接法规规则与保险产品条款的受控标签体系，并按已确认的精算业务口径实现自动识别和一致性校验。

## User Scenarios & Testing

### User Story 1 - 从产品名称识别基础分类 (Priority: P1)

精算师上传产品条款后，系统根据正式产品名称识别业务大类、主要险种类型、设计类型、个人或团体、主险或附加险，以及互联网专属和费率可调身份。

**Why this priority**: 产品名称是产品分类标准，也是法规适用性筛选的第一入口。

**Independent Test**: 输入覆盖寿险、健康险、意外险及修饰属性的产品名称，验证返回稳定的受控代码和证据来源。

**Acceptance Scenarios**:

1. **Given** 名称为“人保健康长期补充团体医疗保险（费率可调）条款”，**When** 识别标签，**Then** 返回健康保险、医疗保险、团体、主险、费率可调。
2. **Given** 名称为“人保健康附加互联网重大疾病保险条款”，**When** 识别标签，**Then** 返回健康保险、重大疾病保险、附加险、互联网专属。
3. **Given** 产品名称无法识别，**When** 生成标签，**Then** 使用 `unknown`，不得猜测具体产品类型。

### User Story 2 - 从条款识别期限和特殊属性 (Priority: P1)

系统从完整产品条款识别长期或短期、健康险监管期限分类、续保类型、税优身份以及已确认的特殊属性。

**Why this priority**: 这些属性决定长期、短期、保证续保和税优法规是否适用。

**Independent Test**: 使用包含不同保险期间、保证续保和税收优惠表述的条款文本，验证标签及一致性约束。

**Acceptance Scenarios**:

1. **Given** 健康险保险期间一年且不保证续保，**When** 识别期限，**Then** 返回短期和短期健康保险。
2. **Given** 健康险保险期间一年但保证续保，**When** 识别期限，**Then** 返回长期和长期健康保险。
3. **Given** 条款明确适用商业健康保险个人所得税优惠政策，**When** 识别特殊属性，**Then** 返回税优健康险。

### User Story 3 - 法规和产品条款共享条款主题 (Priority: P1)

法规条目和产品条款使用相同的受控条款主题代码，以便后续只向审核模型提供相关条款及必要上下文。

**Why this priority**: 共享主题是减少无关上下文并保持召回率的前提。

**Independent Test**: 将常见条款标题映射为主题，并验证法规元数据主题可以写入知识库 chunk metadata。

**Acceptance Scenarios**:

1. **Given** 条款标题为“等待期”，**When** 标注主题，**Then** 返回 `coverage.waiting_period`。
2. **Given** 条款标题为“续保”且正文包含不保证续保，**When** 标注主题，**Then** 同时返回续保主主题和不保证续保子主题。
3. **Given** 法规元数据包含条款主题，**When** 转换为检索节点，**Then** 节点元数据保留受控主题代码。

### User Story 4 - 检测标签矛盾 (Priority: P2)

系统检测产品名称、责任、期限和特殊属性之间的确定性矛盾，不自动改写产品分类。

**Why this priority**: 名称与责任不一致本身可能是审核问题，不能被分类器静默掩盖。

**Independent Test**: 构造名称与责任类型、健康险期限分类、费率可调身份矛盾的标签，验证输出具体警告。

**Acceptance Scenarios**:

1. **Given** 医疗保险名称但不存在医疗责任且仅有疾病定额责任，**When** 校验标签，**Then** 保留医疗保险分类并输出名称责任不一致警告。
2. **Given** `long_health` 与 `short_term` 同时出现，**When** 校验标签，**Then** 输出期限分类冲突。

### Edge Cases

- 产品名称缺失、被截断或只有文件名。
- 产品名称同时出现多个险种关键词时，以正式险种后缀和更具体类型为准。
- 一份产品具有多个期限选项，但长期/短期最终只能二选一。
- 条款文本不完整时，未发现特殊属性不得直接解释为 `false`。
- 条款标题不规范时允许使用别名映射；低置信度时不得强行标注具体子主题。

## Requirements

### Functional Requirements

- **FR-001**: 系统 MUST 使用稳定代码表示产品标签，并提供中文显示名称。
- **FR-002**: 系统 MUST 从产品名称识别业务大类和主要险种类型，且重大疾病保险是疾病保险的子类。
- **FR-003**: 系统 MUST 保证产品侧个人/团体、主险/附加险、长期/短期分别为互斥单选。
- **FR-004**: 系统 MUST 支持一个产品具有多个期限形态和多个精确期限选项。
- **FR-005**: 健康险 MUST 按保险期间与保证续保共同确定长期或短期健康保险，并与通用长期/短期保持一致。
- **FR-006**: 系统 MUST 从名称识别互联网专属和费率可调，从完整条款识别税优健康险。
- **FR-007**: 续保类型 MUST 限于无续保、不保证续保、保证续保和未知。
- **FR-008**: 系统 MUST 保留责任构成，但多种健康责任只作为派生事实，不作为持久标签。
- **FR-009**: 系统 MUST 提供受控的条款主题层级，并允许一条条款具有多个主题。
- **FR-010**: 法规知识库 chunk metadata MUST 能携带与产品条款相同的主题代码。
- **FR-011**: 每个自动识别标签 MUST 能记录来源、证据和置信度。
- **FR-012**: 确定性矛盾 MUST 产生校验警告，不得静默改写名称确定的主要分类。
- **FR-013**: V1 MUST NOT 引入续保费率保证、条件续保、参数可调、调费方向或持久化多健康责任标签。

### Key Entities

- **ProductTags**: 产品基础分类、期限、特殊属性、识别证据和一致性警告。
- **TagEvidence**: 标签值的来源、原文证据和置信度。
- **TermOption**: 固定期限、保至年龄、终身或保证续保期间等结构化期限事实。
- **ClauseTopic**: 法规与产品条款共享的受控主题代码。
- **Clause**: 产品条款内容及一个或多个主题标签。

## Success Criteria

- **SC-001**: 已确认的名称样例基础分类准确率为100%。
- **SC-002**: 个人/团体、主险/附加险、长期/短期不存在双值状态。
- **SC-003**: 健康险长期/短期分类覆盖“超过一年”“一年且保证续保”“一年且不保证续保”三个边界场景。
- **SC-004**: 互联网、费率可调、税优健康险均返回标签证据。
- **SC-005**: 常见条款标题能够映射到稳定主题代码，未知标题安全返回空主题或通用主题。
- **SC-006**: 新增测试通过，现有文档解析和合规测试不回归。

## Assumptions

- 当前审核对象仅为产品条款，暂不建模产品说明书、精算报告等材料类型。
- 产品正式名称是主要险种类型的分类标准；条款责任用于一致性验证。
- 互联网专属和费率可调可由产品名称可靠判断。
- 税优健康险通过完整产品条款中的明确税收优惠表述判断。
- 银行代理渠道等无法由产品条款可靠获得的身份暂不自动标注。
