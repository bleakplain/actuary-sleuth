# Research: 产品标签驱动审核主链现状

**Date**: 2026-07-28
**Scope**: 当前代码、v5 知识库、真实产品条款与既有测试基线。

## 1. 已有能力

- `ProductTags` 已覆盖产品大类、子类、设计类型、期限、个人/团体、主险/附加险及特殊属性，并保留证据。
- `applicability.py` 已实现法规限定标签解析和三态匹配。
- `layered_retrieval.py` 已实现适用性与主题分层，并保留检索来源和回退轨迹。
- DOCX、PDF 和旧 DOC 均可进入产品解析；旧 DOC 临时转为 DOCX 后复用结构解析。
- v5 为当前唯一法规知识库版本，现状为 25 个文档、171 个 chunk。

## 2. 真实产品解析基线

`/Users/plain/work/actuary-assets/products` 主目录有23个可直接解析文档和1个ZIP归档。归档内12个旧DOC中，9个与主目录DOC相同，3个是主目录PDF/DOCX产品的额外格式版本；按文件版本合计共有26个可解析文档：

- 11 个 DOCX；
- 3 个 PDF；
- 12 个旧 DOC。

主目录23个文件和归档内12个旧DOC均已逐份解析成功。剔除3组重复格式产品后：

- 1,406 个条款块中 421 个有主题，覆盖率 29.9%；
- 985 个条款块主题 unknown，占 70.1%；
- 按标题和正文字符量计算，主题 unknown 内容占 64.3%。

因此第一版必须保留所有 unknown 条款，不能把主题不匹配直接解释为无关。

## 3. 主要结构缺口

- 条款主题代码当前隐含在关键词 JSON 的键中，没有独立版本载体。
- 当前解析结果缺少统一、稳定且跨运行可复现的 `clause_id`。
- 已有检索以 chunk 为主，目标审核需要按法规条款单元聚合。
- `checker.py` 仍以整份文本和旧输出模型执行 LLM 判断，缺少法规级审核包和严格证据校验。
- `rule_engine.py` 仍代表旧的平行确定性判断路径；其监管语义不可信，不能迁移到新主链。
- API 与前端已有部分 degraded 字段，但尚不能完整表示单元失败、审核 incomplete、版本和未审核范围。

## 4. 数据与版本原则

- 法规原文和已验收元数据是唯一监管依据。
- 适用标签表示限定范围，涉及标签只表示关联；当前 v5 尚无涉及标签数据。
- `article_number` 优先来自 chunk metadata，缺失时使用转换或解析生成的 `section_path`。
- 主题体系、主题关系、知识库和精算验收集均必须独立版本化并写入报告。

## 5. 测试基线

2026-07-28 在当前主工作区运行 `pytest scripts/tests/ --no-cov -q`：

- 703 passed；
- 24 failed；
- 13 errors；
- 4 skipped；
- 2 deselected。

主要既有失败来源：

- SQLite 配置路径在当前环境不可写；
- Ollama 未启动导致真实向量索引测试失败；
- 合规 E2E 依赖未运行的 API/外部 LLM；
- 少量认证、权限和 memory 测试为既有环境或 Python 3.14 兼容问题。

本功能的标签、适用性、分层检索、法规转换、DOC/DOCX/PDF 解析相关定向测试通过。执行阶段以“不增加基线失败”为最低要求，并为新主链建立完全离线、可重复的单元与集成测试。

## 6. 关键设计结论

1. 采用唯一审核主链，旧链只在切换前做影子对照。
2. 产品标签先过滤法规，条款主题再路由产品内容。
3. 未知事实和未知主题一律保守保留。
4. 逻辑审核单元是法规条款单元；第一版一单元一 HTTP，最多并发 5 个。
5. 确定性程序只提取事实，最终法规结论由同一 LLM 主链产生。
6. 单元失败不阻断其他单元，但整份报告标记 incomplete，不能显示为合规。
