## 四、实现后终审结论

上述问题均已在计划或实现阶段处理。2026-07-28 的最终只读审查额外发现并修复：

- 一年期保证续保健康险的长期监管分类一致性；
- 已识别保险产品的普通型默认值；
- 通用提示语误识别为产品名称；
- DOCX 合并单元格造成的重复未分类正文；
- 保证续保期间误取“届满后60日申请窗口”；
- API 不完整报告和前端即时报告遗漏解析追溯字段。
- 候选报告使用数据库不允许的 mode，导致真实 SQLite 永远无法保存；
- Arrow 与 Pandas 的 nullable 整数类型漂移，导致真实 v5 受控指纹恒不匹配；
- 认证密钥为空时 JWT 可使用空密钥、开发多 worker 解析凭证不稳定；
- SSE 后台线程启动失败缺终态、保存超时可能形成孤儿报告；
- 多请求各自并发5导致模型调用放大；
- 合规报告缺少用户所有权隔离；
- 产品上传和富文本解析缺少大小边界且阻塞 async worker。
- 跨页重复编号未补回缺失标题，以及已进入编号条款后被章节标题误提前截断；
- 纯一级编号产品无法形成条款，金额、比例、年龄和普通数据表存在误切风险；
- 条款内数据表的 `remark` 未进入规范全文，却错误签发完整覆盖证明；
- 自定义 staging/backup 路径可与线上 references/v5 重叠。

这些问题均已修复，并增加真实 v5、真实 SQLite、认证、并发、终态、权限、资源边界、编号正反例、表名覆盖证明和路径隔离测试。最终35次真实产品解析均满足来源记录唯一完整归属；终审未发现剩余 P0/P1 阻断项。未分类正文比例、跨 worker 可取消调用与共享配额、报告分页、深层解析资源预算、密钥轮换和精算验收签收已记录为后续优化或切换门，不得据此提前切换默认入口。

## 六、2026-08-03 法规适用性反馈处理

精算反馈指出，法规要求产品具备的正确属性不能反过来作为适用前提，否则会漏掉最需要检查的错误设计。例如短期医疗险错误设置费率可调、寿险错误出现保证续保时，仍必须召回对应法规。

本轮采用以下统一规则：

1. `适用标签` 只承载法规主体范围；
2. `风险触发标签` 承载费率可调、保证续保、特定疾病、院外购药和恶性肿瘤专项等实际设计事实；
3. `检查目标标签` 只描述 LLM 要核验的合规要求，不参与排除；
4. 主体匹配或风险触发任一成立即保留；风险事实 unknown 时保守保留；
5. 复杂跨维度 OR 第一版不做激进表达，无法安全建模时扩大候选范围。

代码终审补充修正了两处语义边界：

- 院外购药改为表述涉及事实：完整条款出现“院外购药”或“药店”任一表述即为 true，两者均未出现时为 false，覆盖证明未通过时为 unknown；true 不代表产品承担该责任；
- 未识别的风险触发单独记录为 `unknown_risk_triggers`，不污染普通产品标签缺失维度；主体已经明确匹配时仍为 applicable。
- 2026-08-04：从中保协发〔2020〕73号 PDF 提取31项疾病定义与14项术语释义，形成版本化受控定义库；新增 `critical_illness_definition_term` 风险触发。当前阶段只判断产品条款是否需要进入新版重疾定义检查，不审核精算报告。

法规源经 artifact-tool 修改和可视化核验后，只使用2026 Excel 重建正式 v5。当前为25部文档、174个法规单元，构建 manifest、LanceDB 和 BM25 身份一致；旧正式库已留存可验证备份。

验收迁移遵循保守原则：170条已签收产品标签继续冻结；新增69条风险事实单独验收。旧法规适用性表中凡状态为“有异议”、精算修正非空或审核意见非空的法规单元，均按单元级将全部产品行转为待复核。37个旧反馈单元在拆分后对应39个新单元，历史意见全部保留，不以旧表摘要和失效公式作为迁移依据。
