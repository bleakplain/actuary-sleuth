# Feature Specification：知识库问答体验重整

**拟用分支**：`codex/041-qa-knowledge-experience`（尚未创建）

**日期**：2026-10-21

**状态**：已获准执行，尚未发布

**用户输入**：希望获得类似 ima 知识库的问答体验，先给优化计划。

分支编号扫描的最大值为 038，但主仓库已有 039、040 规格，为避免编号歧义使用 041。本文将既有 `038-professional-regulatory-qa` 的要求收敛为可交付的体验目标，不修改合规审核的承诺。

## 产品定位与边界

面向保险产品、精算与法规资料使用者，提供自然、连贯、有来源的“基于导入资料的知识问答”。不是逐条正式合规审核，不承诺对未知效力资料作现行法鉴证。参考 ima 的使用体验，不声称复制其未公开技术，亦不声称已经与其效果相当。

原要求中的逐陈述验证保留来源与关键事实安全底线，但不再把所有表达差异、无关背景或风格评分都等同于必须阻断回答的风险。任何未来调整均要用真实答案和反例验证，不能用“供参考”标签代替正确性。

## User Stories

### US1：自然提问，得到有用且有据的解释（P1）

用户用口语、简称、概览、比较或错误前提提问，能得到直接结论、必要范围与例外及可点击依据，而不是一大段原文或笼统的“回答不了”。

**独立测试**：使用已确认资料与问题，检查关键结论、来源、条件和未回答部分；不依赖前端流式。

- 资料充分时，解释涵盖问题所需的关键维度，不以找到一段相关条文代替完整回答。
- 错误前提应被有据地纠正；“并不是所有产品都适用”可以是完整答案，不应强求用户先给产品再作任何说明。
- 问法宽泛但仍可提供分类概览时先回答；只有缺少的条件会实质改变结论时，才询问一个最必要的问题。
- 数值上下限、适用主体、已知例外与证据冲突未核清时，不把猜测当结论。
- 没查到、模型/网络出错、法规效力未知分别说明，不把技术故障说成用户资料不足。

### US2：响应及时，多轮稳定，不展示未核清的高风险草稿（P1）

用户提问后及时知道真实进展，常规问题无需等待多次模型互相检查；可以追问“儿童呢”“换成医疗险呢”，也可以切换主题或取消。

**独立测试**：固定语料/模型/机器，回放单轮、指代、条件替换、主题切换、取消与重连。

- 原问、时间、地域、产品和否定条件不因改写丢失。
- 默认回答简洁，支持按需展开；不能以截断句子/表注换速度。
- 进度是真实阶段，不把显示进度或打字动画算作正文响应。
- 如采用分段交付，仅交付已完成必要检查的独立段落；不得先发有争议数字再事后撤回。
- 历史记录、屏幕正文和引用保持一致，取消后不串入新会话。

### US3：少量人工即可判断改进是否有效（P1）

维护者不用逐条整理整本法规手册，也不用手写大量标准答案；通过少量关键点确认、自动变体回放与差异报告决定是否发布。

**独立测试**：固定问题族分组、保存初稿/修订/交付差异和成本，确认失败不会从统计分母消失。

- 重用已有 30 题候选集，但机器预标不是金标；按问题族区分调参与封存，封存内容不用于开发。
- “完整解读、部分解读、原文参考、必要澄清、无法交付”分开计数。
- 模型提供的自评分仅辅助筛选，不作为准确率证明。
- 有人工确认的关键证据/结论、反例与多轮场景后才进入限定试用；单元测试通过不是质量验收。

### US4：独立知识范围与可回滚交付（P1）

用户继续使用更大范围的 QA 法规库；合规检查不受问答体验改造影响。换版本时能确认运行的代码、模型和库版本，并可回滚而不覆盖新对话。

**独立测试**：跨库哨兵、来源权限、历史时点、版本切换、服务重启和会话持久化测试。

- 不混用 QA 与合规库，不因 QA 失败回退到合规库。
- 未核定效力不伪装为“现行有效”；编纂标题不冒充实际法源。
- 原始资料、旧发布物和用户对话数据库不被实验覆盖；第 316 页识别码继续忽略。
- 未批准不增加新供应商、新资料外发或付费调用；不会自动上传 ima。

## Requirements

- FR-001：默认交付基于资料的解释，不默认运行一套正式审核流程。
- FR-002：每个关键法规事实有真实、可定位且与结论相关的引用；引用存在不等于结论正确。
- FR-003：一般释义或无关背景不能单凭词面疑点阻断；真实错引、关键数字/范围/例外冲突继续阻断相应结论。
- FR-004：复杂问题覆盖不同维度，缺口明确；不对每种口语问法追加独立规则。
- FR-005：普通问题优先短路径，有界补充与纠错，不无限追问模型。
- FR-006：未知、不可用、部分有据与完整回答使用一致且诚实的交付语义。
- FR-007：支持有边界的多轮理解和取消，不泄露或混淆会话/用户/知识库范围。
- FR-008：质量、延迟、调用次数、token 和费用同时记录，测试、模型与资料版本可复现。
- FR-009：首期不建设全书人工本体，不迁移数据库作为体验改善的前提。
- FR-010：未通过限定样本质量与安全门槛不得自动替换现用入口。

## Success Criteria（试用目标，不是已取得成绩）

- SC-001：人工确认的 20 个可回答锚定题，至少 18 个关键点正确且完整；调参/封存各 10 题，封存至少 9/10。每组另有 5 个边界题，须均不编造关键法规事实并按预定策略纠正、澄清或说明缺证；技术失败不能算正确拒答。
- SC-002：20 个可回答题中，系统性误拒最多 1 个；已知 3 类失败探针各重复 3 次均能合理交付，不计入独立样本数。
- SC-003：关键数字、上下限、范围、例外、跨库/权限、历史版本反例中无已发现关键错误放行。样本零错误不等于总体零风险。
- SC-004：普通问题完整正文 P50≤8 秒、P95≤15 秒；复杂问题完整正文 P95≤25 秒；先满足质量门槛，再讨论速度。另报全部请求终止延迟和失败率。
- SC-005：真实首进度 P95≤1 秒；如实施分段交付，首段必须有实质内容并通过必要检查，不能用进度或免责句充数。
- SC-006：QA/合规隔离、权限、引用定位、多轮条件、取消与保存一致性测试通过；完整后端、类型检查、前端测试构建不新增失败。

正式内容验收按问题族而非最好的一次回答评分：冻结版本后，每题及预定追问运行 3 次，均满足关键点才记该题通过；口语变体不增加独立样本数。系统性误拒按出现过流程误拦的问题族计数，模型错误与技术失败另外报告，并同样计入完整解读未通过。具体批次与调用上限见 plan.md。

## Assumptions 与待确认事项

- 用户后续已批准执行，并要求当前会话助手参与模型对照；采用开发集参考作答，不冒充独立 API 实验或人工金标。执行补充见 plan.md；默认模型、付费与发布不自动变更。
- 先评估同供应商公开免费候选，收费候选不是继续离线工作的前置条件；账户可用性/限流要在执行前确认。
- [NEEDS CLARIFICATION] 若免费路线达不到门槛，是否允许封顶的小额模型对照预算？计划先给可选上限，未批准不消费。
- [NEEDS CLARIFICATION] 是否允许将同一资料上传 ima 做正式对照？默认不允许；缺少对照时只说达到自定试用门槛，不说“等同 ima”。
- 首轮人工关键点确认估计 1.5–3 小时；模型对照与最终结果复核另估 2–4 小时，总计先预留 3.5–7 小时，争议多时重新估算。若无复核人员，只能做工程/内部体验验证，不能声称专业准确率达标。
- 法规效力全库核定是另一项工作，不混入本轮低人工体验改造的工期和质量承诺。
